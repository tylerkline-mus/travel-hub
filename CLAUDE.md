# Travel Hub — project guide for Claude

Tyler's personal trip planner + travelogue. Phone-first web app on GitHub Pages, data in his Google Sheet.
Read this before changing anything. Keep it current when the structure changes.

## Architecture

- `index.html` — the entire app (vanilla JS, no build step). Leaflet 1.9.4 from cdnjs for maps, OpenStreetMap tiles (CARTO now needs a key — don't switch back).
- `review.html` — the review page someone opens from a chapter's review link (separate file, own sea-glass look: Bricolage Grotesque headings, Figtree text, coral = yes, olive = what it is; see "Chapters and review links").
- `sw.js` — service worker: app shell network-first, assets cache-first, OSM tiles cached as viewed (offline maps). Bump `CACHE` when shell files change.
- `apps-script/Code.gs` — Google Apps Script backend bound to the Sheet, deployed as a web app (Execute as me, Anyone). The app POSTs `{action, token, ...}` as text/plain JSON; the Shortcut uses GET params. Script Properties: `TOKEN` (passphrase), `PLACES_KEY` (Google key: Places API (New) + Routes API).
- Writes are optimistic: applied locally, queued in an outbox (localStorage), flushed to the script. A server error that means the Sheet was busy (lock timeout, too many requests, service errors) is retried like no signal, never dropped; other server errors are dropped with a toast. Google lookups (`refreshItem`, `updateItem` with `_link`) run before taking the lock, so saves don't queue behind them (Oct 2026: seven new suggestions being looked up made Tyler's edits time out). Deletes go through `undoable()` (6 s undo; Undo puts back only the rows that delete removed or changed, never a whole snapshot — a snapshot once brought back a stop already deleted in the Sheet).
- Google Places lookups happen server-side (`resolveText`): expands maps.app.goo.gl links, parses name/coords, Text Search → place id, address, hours (periods + weekday text), types, website. Airports: `airportLookup(code)` cached in Script Properties. Routes: `routes` action, cached in the Routes tab.

**Script changes need Tyler to redeploy**: copy raw `apps-script/Code.gs` → paste in Apps Script → run `setup` (adds missing columns/tabs non-destructively) → Deploy → Manage deployments → ✏️ → New version. Always tell him when a change needs this. App-only changes go live on push (GitHub Pages, ~1–2 min).

**Shortcuts gotcha:** Shortcuts mangles a Get Contents of URL address built from inserted variables (everything from the inserted value on is dropped), so shortcuts POST a **JSON request body** to the bare /exec URL instead — `doPost` parses it. (`b64=` unpacking in `handle()` still works but isn't needed.) `add` accepts `trip=auto` (current-or-next trip) and refuses empty saves; errors list the fields received (`receivedSummary`).

Read only the columns needed, e.g. Items `A:H` + `P:V` + `Y:AB` (id…address, day…notes, end_day…priority) — check the header row first since columns can shift.

## Ask Claude (built Oct 2026)

- Idea `status`: `open` · `ask` (Ask Claude toggle on) · `answered`. Toggle saves immediately; turning it off goes back to `answered` if the idea has suggestions, else `open`.
- Suggestions = non-fixed children of an idea (`isSuggestion`, `suggestionsOf`). - The "check my asks" procedure lives in Tyler's `travel-hub-asks` skill (holds the Sheet ID — never put it here).

## I'm here (logging)

- Opening **I'm here** for today asks for location right away: lists sort by distance, the saved place you're standing at is preselected (planned < 150 m, other saved < 75 m), and **Around you** shows nearby places from the script's `nearby` action (Places API (New) Nearby Search, closest first; the app widens 80 → 300 → 1500 m until ≥3 turn up; script caps radius at 1500; lookup errors show in the status line; same name within 50 m is shown once). Nearby Search rejects non–Table A types in `excludedTypes` (e.g. `route`, `street_address`) — that broke every lookup until Oct 2026. Picking one logs it with `place_id`, name and coords. Below that, **Just this spot** drops a pin at the phone's coords, named by OpenStreetMap reverse geocoding from the phone (`hereName`: street, else neighbourhood, else town; "Dropped pin" offline) — no script change; it logs as `found` with no `place_id` (the script still links it to a saved item within 75 m).
- Live times: if the phone was within 300 m of the stop when logged (and no time was typed), `time` is filled with now. `logged_at` is the phone's own timestamp (sent by the app), so offline queueing doesn't shift it. Backfilled stops get no automatic time — the poster's time-based credits rely on this.
- Shortcut: `GET ?action=here&format=text&token&(text=<Maps link>|lat&lng)[&note][&trip]` logs to the trip happening today (±1 day). A shared link is resolved (`resolveText`) and matched to a saved item by place_id (or within 40 m); a location matches a saved item within 60 m, else the nearest Google place within 60 m, else the street/neighbourhood (`spotName`: Apps Script `Maps.newGeocoder` reverse geocode, Nominatim fallback — Nominatim alone came back empty from Apps Script), else "Somewhere". Time = when it arrives. Ignores a repeat at the same spot within 30 min (check + write under one lock, so a double/triple tap logs once; `withLock` is re-entrant via `LOCK_HELD`). One shortcut does both (share sheet input → link, no input → location); steps in SETUP.md §7. **Close calls**: with `ask=yes` and no saved match, if the two nearest Google places are < 25 m apart in distance, `here` logs nothing and returns one line per choice, each starting `📍 ` (max 6 + `📍 Just this spot`); the shortcut's Choose from List sends it back as `pick` (matched by title against a fresh 60 m Nearby Search; Just this spot → street name). The repeat check runs before the list is offered. "Send to Trip" (§6) is the share-sheet route for saving places.

- **Not here?** (Oct 2026): a top-level stop's sheet has "Not here? Pick the right place" (`pickRightPlace` / `swapLogPlace`): saved trip places within 150 m, then the script's `nearby` around `here_lat/here_lng` (else the stop's own coords; 60 → 150 → 400 m until ≥5). Picking rewrites the stop's place fields via `updateLog` (saved place → `item_id`, origin planned, item done; the old planned item goes back to open if nothing else logs it). Exists because indoor GPS is off by 20–50 m and strip-mall storefronts are ~10 m apart.

## Out wandering (built Oct 2026, on the trip)

- Why: Tyler doesn't log pharmacy runs or aimless walks, so the gap after a stop read as hours *at* that stop (Lingered longest) and the poster drew a straight walk; he'd been logging "back at the hotel" as a reset.
- **Out wandering** button beside I'm here (`logWander`; on a past day it opens `openWander` to type the time). Saved as a normal Log row: `category: 'Wandering'`, title "Out wandering", no lat/lng, so no script change (`isWander`). Live: seq = after everything logged; backfilled: after the last stop before that time (fractional seq). Shown in the Log as a dashed row (not numbered, no leg button); tap to change the time or remove. Excluded from stop counts.
- Poster (`recapData`): a wander ends the stop before it (`wanderAt`) and marks the next leg `wandered`, drawn by `wanderLeg` as a loose dotted meander (no Routes lookup for it). A wander that starts and ends at the same spot (out from the hotel and back) is drawn as a loose dotted loop off to one side (~70 px, direction from the seed), since a meander between two equal points draws nothing. `data.wandered` = minutes from each wander to the next timed stop.
- **Lingered longest** now: ends at a wander if there is one (up to 8 h); otherwise only counts if the gap fits the place (`lingerCap`: 45 min shops/bakeries/hot dogs, 2 h cafés/bars, 2½ h restaurants, 3 h museums/pools/churches/parks). Stays never count. New credit **Wandered** (on by default, from 45 min): "about 3½ hours, off the map".

## Adding a stop after the fact (Oct 2026, on the trip)

- I'm here on today has a **I'm here now / Earlier today** switch (`earlier`). Earlier: hides the location bits (`#h-live`: where you are, Around you, Just this spot), clears the auto-pick, and needs a time. Saving ignores the phone's current position (`pos = earlier ? null : livePos`), so a typed name isn't pinned where you're standing and `here_lat` stays empty. On a past day the sheet is already in this mode (time optional there).
- Order: a stop with a time added after the fact goes after the latest-timed stop before it (`seqForTime`, midpoint seq, so seqs can be fractional strings like "1.5"; Reorder renumbers). Live stops and live wanders go after everything (max seq + 1), not at `tops.length`, so fractional seqs never collide.

## Daylight (built Oct 2026)

- Each day card in Days shows sunrise, sunset and hours of daylight (+ change vs yesterday) under its heading (`daylightRow`). Computed on the phone (`sunTimes`, sunrise equation with −0.833° refraction; checked against Louisville, Tokyo — within ~1–2 min), so it works offline. Place = where you wake up (`stayForMorning`), else tonight's stay, else the day's first planned stop with coords (`dayPlace`); no place → no row. Times in the trip's timezone (`clockIn`). Polar night/day handled.

## Kept with a stop (photos, sounds, souvenirs — built Oct 2026)

- Sheet tab **Artifacts**: id, log_id, trip_id, kind (photo | sound | souvenir), title (souvenir name), note, file_id, mime, duration (s), seq, created, updated. Files go to Drive `Travel Hub/<trip name>` (`tripFolder`, folder ids in Script Properties `FOLDER_root` / `FOLDER_<tripId>`), never shared. Script actions: `upload` (b64 → Drive file + row; idempotent by id; a souvenir may have no file), `file` (returns `{mime, b64}` — the only way the app reads a file), `updateArtifact`, `deleteArtifact` (trashes the file). `deleteLog` trashes a stop's artifacts. `bootstrap` returns `artifacts` (missing = old script).
- App: up to 4 photos (`MAX_PHOTOS`, shrunk to ≤1600 px JPEG on the phone by `shrinkImage`), sounds up to 60 s (`soundButton`, MediaRecorder; iOS gives audio/mp4), souvenirs ("Brought home", name + optional photo). Added in the log entry sheet (**Kept**, `keptBlock`/`bindKept`, saves immediately) and in **I'm here** (photos + a sound, sent after the stop with `local.id`). Log list shows the first photo as a thumbnail.
- Files: IndexedDB `travelhub-files` (`blobs`) holds files waiting to upload and doubles as the cache; `artURL` → phone copy or `file` via the script; any `[data-art]` img/audio is filled by a MutationObserver (`hydrateArt`). Outbox `upload` ops carry `hasFile`; `flush` attaches b64 at send time (localStorage never holds file data).
- Old script: artifact ops that get "Unknown action" are **parked** (`th_parked`) and kept visible; once `bootstrap` returns `artifacts`, they're re-queued.
- Poster credit **Brought home** (`brought`): souvenir names on the poster's stops. Photos are not on posters (Tyler's call, revisit after a trip).
- **Never write sw.js with `open(p,'w').write(open(p).read()…)`** — that truncates before reading and emptied sw.js once (Oct 2026). Bump `CACHE` with sed or read first.

## Recap poster (built Oct 2026)

- Draws from the Log once anything is logged, otherwise from the plan (planned stops, tours; musts in color).
- Design (deliberately not the app's cream/terracotta): ECM-sleeve restraint, routes as a pen line (real paths from the Routes cache, else a gentle bow), stays as squares, found-along-the-way as open rings, loved places in the accent with hand labels in italic. Looks: Fog / Night / Riso (accent overprinted with multiply, slightly off register). One typeface: Familjen Grotesk, loaded only on this screen. Paper grain is a seeded noise pass.
- Data: a "score" strip (one stroke per day, length = stops, colored top = loved), coordinates and scale bar, a locator inset in the emptiest corner when zoomed to the densest area (`recapCluster`), and **credits** (`recapCredits`, `CREDITS`): names not numbers, set like a record sleeve (label left at 62% ink, value right). Each is offered only when the data supports it and is a switch on the Poster screen (`th_poster[trip].credits`); Favorite discovery can be picked (`.fav`). Time-based credits use only `time` (live-logged or typed). Home away from home = the densest 700 m of stops named by Nominatim reverse geocoding (`recapHood`, memo `th_hoods`). Log notes on loved places print under their names (`.notes` toggle). `recapNotes` (old prose) is unused. Log has a `category` column (from the item, the picked nearby place or a Maps link) for Most often.
- Per-trip choices (size, look, zoom, ground, own line) live in localStorage `th_poster`.
- **Ground** (`ground`: none | water = "Water and names" | roads = "Plus roads", default roads). `groundScale`: city < 40 km, region < 400 km, else country. Country: Natural Earth 1:50m from `world-atlas@2` on jsDelivr (land tint, coastline, dashed borders; rings unwrapped across the date line) + OSM city names. Region: OSM coast, named rivers (< 260 km spans), city/town names, motorways/trunks with roads on, plus the world map's borders. City: OSM coast, lakes/ponds > 80 m, rivers/canals, suburb/neighbourhood names, primary+ roads with roads on (`loadOSM`). Place names are upright, letter-spaced, 50% ink, placed only where free (`drawPlaceNames`); cities may shift above/below. The ground layer fades at the top and bottom of the drawing. The locator inset always gets the country outline.
- **Land and water** (Oct 2026) is a switch, **Shade land and water** (`prefs.shade`; trip posters default off to keep the constellation look, Look back map default on via `p.shade !== false`; hidden when Ground is None). Off = hairlines only, plus the old faint `hint` land tint on country maps. When on, each look has `land` and `water` tones (`paintSurface`, called first in `drawGround`, and in `drawWorldShifted`). Country scale: water wash, then Natural Earth land (paper, then the land tone). City/region: `rasterSurface` draws OSM coastlines on a half-size mask, labels the areas between them, and decides each by which side of the coast it's on (land is left of a coastline way); areas no coast decides, or with mixed votes (a leak from data cut short), ask the world map (`inLand`, sampled on a grid); at region scale a big area that flatly contradicts the world map follows the world map. The fetched box's edge (`ground.osmBox`) is a wall too. Lakes/wide rivers (natural=water ways, relations joined by `joinRings`) are filled on top; inner rings go back to land. `groundBox(pts, size)` widens the fetch to the poster's shape (wide for post, tall for story) so the coast reaches the edges.
- Every stop gets an italic name label when there's room (loved first and larger, then ones with notes, then the rest; max 10 post / 12 story). Fetched by the phone on the Poster screen only, kept in the Cache API (`travelhub-ground`, which `sw.js` leaves alone). Tests mock both: `npm i world-atlas@2` and a hand-made Overpass fixture.
- **Frames** (`prefs.frame`: `{kind: all | stay(id) | place(lat,lng,r km) | dates(from,to), name, sliceId}`; `frameTest`, `recapData(t, frame)`). Places come from `recapAreas` (stops within 30 km grouped, named by most common city, else region). A slice's score strip shows only the slice's own days (first to last day in the frame; Tyler asked, Oct 2026), uses the slice's dates in the top line, and its name becomes the title with the trip's name small above. The locator inset shows the whole trip with the slice boxed when the trip is ≥3× wider. Saved slices (`prefs.slices`) are per device (localStorage), not in the Sheet.
- **Unforgettable** (`rating: 'best'`, Oct 2026, Tyler asked for a tier above Loved): counts as loved everywhere (`mark`), plus `best` on the stop: a bigger accent dot with a ring, its name labelled first in a larger italic 500, and Favorite discovery prefers it. Rating picker is `#lg-rate` (buttons size to their words).
- **Chores** (Oct 2026, from Tyler's first real days in Reykjavík): `isChore` / `CHORE_RX` = stays, airports, terminals, transportation, stations, supermarkets, groceries, pharmacies, post offices, government offices, banks, "Somewhere"/dropped pins (by Log `category`/title; loved is never a chore). ## Chapters and review links (built Oct 2026)

- **Chapter** = a stretch of a trip: dates + "places within N km (default 25) of where you stay". A lens only; items never move. Membership (`inChapter`, same rule in the app and `Code.gs`): dated items by date overlap; children follow their parent; undated places by distance to the chapter's stays (stays with a *night* inside the chapter: checking in on the last day is the next leg, `chapterStays`); no coords → city match; undated ideas with no place → in. Trip header shows chapter chips (`chapterRow`); picking one narrows Days, Saved and Map (`scopedTop`, `scopedDays`, `ui.chapter` in localStorage `th_chapter`). Edit · Share opens `openChapter`.
- **Review link** (Shares): `review.html#s=<token>&u=<script url>`, made in the chapter sheet (Send link uses the share sheet, Preview opens it, Turn off sets `revoked`). The token is 18 random chars made on the phone. Deleting a chapter turns its links off. (The app's `addShare` sends `{share: …}`, which is why the review door uses `reviewKey`: an earlier version keyed on `share` and refused Tyler's own Make a link.)
- **Script door**: a request with `reviewKey` (and no `token`) only reaches `REVIEW_ACTIONS` (`review`, `react`, `suggest`); everything else answers "Not available from a review link".
